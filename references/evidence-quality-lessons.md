# 证据质量：采集不可重来，所以可判读性必须在采集时保证

2026-08-17，游戏探针试点的第一场数据出炉：8 次"死亡"里 3 次是误判，敌人识别
大半是 low/medium 置信。第一反应是"AI 判得不准"或"阈值没调好"，两个都不对。

真正的病因是：

> **给 AI 的证据本身没有价值。**

AI 的裁定其实全对——它正确认出了那三次是开场过场、训练场匹配、装备菜单。
它判不准的地方，是因为**当时存下来的画面根本没法判**：受击瞬间动态模糊、
大型敌人贴脸占满屏幕、追溯到的"事发前"其实是一秒前的无关时刻。

这不是游戏探针独有的问题。任何"大量采集 → 事后让 AI 提炼"的系统都会踩：
摄像头行为记录、屏幕活动日志、传感器流、会话录制。区别只在于，游戏里一晚
就能暴露，别的场景可能要攒几个月才发现攒的是一堆废料。

而废料是不可逆的——**采集不可重来**。分析层可以重写一百遍，采集当时没存
对的东西，再聪明的模型也救不回来。

---

## 三个根因，三条规则

### 一、单一信号的歧义，事后无法消解

**当时**：只采血条一条。"血条归零"（濒死）和"整片 HUD 消失"（菜单/过场/
加载）在读数上完全一样，都是 0。

**代价**：3/8 的误判。而且这些误判在台账里长得跟真事件一模一样，不看截图
分不出来。

**规则**：**一个信号只有一种解释时才能单独采**。如果同一个读数能对应两种
现实，就必须同时采能把它们分开的第二个信号——采的时候多花几毫秒，事后省
下的是"这条数据到底算什么"的永久悬案。

**但也别过度承诺**：这次的续集是，我以为"三条同步压暗 = 菜单"能判准，实测
发现战斗中 FP/耐力本来就被消耗（读数 1172–1812），跟菜单遮罩（1858）完全
重叠。像素层分不开就是分不开。于是确定性层只保留能判准的那一态（三条全灭
= HUD 消失），其余如实记录读数、交给证据和 AI。
**宁可诚实地说"这里有歧义"，也不要让确定性层假装能判。**

### 二、单帧不是证据，序列才是

**当时**：每次事件存两张图——事发前一秒 + 事发瞬间。

**代价**：事发瞬间必然是最糟的一帧（动态模糊 + 特效遮挡 + 敌人贴脸占满屏），
而"前一秒"在快节奏场景里已经是另一个世界。两张都没用。

**规则**：**证据的时间覆盖要宽于事件本身**。现在存 `-8s / -5s / -3s /
-1.5s / -0.6s / 0 / +1s / +2s` 八帧，各司其职：

| 时段 | 回答什么问题 |
|---|---|
| -8s ~ -3s | **这是什么东西**（敌人还在远处，轮廓完整可辨） |
| -1.5s ~ 0 | **发生了什么**（动作、攻击类型、位置关系） |
| +1s ~ +2s | **结果如何**（倒地提示、死亡画面、还是根本没事） |

实现上是内存里的环形缓冲（保留最近 14 秒），事件确认后才落盘——**没发生的
事不占磁盘，发生了的事有完整前因后果**。

### 三、模糊的帧等于没有帧

**当时**：取"事发时刻那一帧"，取到什么算什么。

**代价**：游戏有动态模糊，战斗中随机某一帧可能糊到看不出敌人是人是兽。

**规则**：**每个时间点都要留候选，并按可判读性挑**。现在每个目标时刻在
±0.7 秒邻域里取所有候选帧，用拉普拉斯方差（清晰度）选最好的一张。成本几乎
为零（0.3ms/帧），收益是把"随机一帧"变成"这个时刻能拿到的最好一帧"。

---

### 四、锚在开放集合上，等于没锚（追加于当日第二轮）

**当时**：血条按"红色像素数"计数。

**代价**：血条**会整体变色**——装备对比界面变粉、区域增益变紫、队友濒死、
中毒、被雨淋、虚血……变色瞬间读数归零，伪造出"98% 暴击"。一场里 4/10 的
重伤事件是这么来的假警报（人根本没受伤，在看地图/买东西/升级）。

**第一次修正**：改锚"空槽"——用户的原话是"应该看空的血条"，因为填充色是
**开放集合**（数不完），空槽像是闭集合。方向对，但实测又翻了车：**空槽是
半透明的**，背景会透过来（雪地场景亮度 102、夜沼场景 45），它同样不稳定。

**最终判据**：锚在**填充段自身的均匀性**上。不管什么颜色，同一段填充是同色
的，而空槽随背景波动——取最左端（必为填充）作参考色，向右找第一处显著偏离
就是边界。段内再按饱和度分实血与余像（余像是去饱和的白影，实血无论橙红还是
粉紫都保有饱和度）。

**规则**：**当某个特征是开放集合（无法穷举），就不要锚在它上面——去找那个
真正闭合的不变量**。这里的不变量不是任何一种颜色，而是"一段填充内部是同质
的"这个结构性质。找不变量比枚举特例便宜得多，也不会在下一个特例出现时崩掉。

推论：**锚点候选也要验证，不能想当然**。"空槽是闭集合"听起来完全合理，实测
才发现它半透明。每个锚点上线前都该在真实数据的极端态上跑一遍。

## 顺带一条：性能不是不采的借口

第一版环形缓冲每帧 137ms（3Hz 就吃掉 41% 单核），看上去只能砍频率或砍质量。
分解后发现瓶颈在 PIL 的 LANCZOS 缩放（47.8ms）——换成 numpy 步长降采样后
**7.7ms，而且分辨率更高**（1920×1080 vs 1600×900）。整帧降到 64ms。

**先量再砍**。凭感觉砍掉的采样质量，就是将来救不回来的证据。

## 落地检查表

新建任何"采集给 AI 用"的通道时，逐条问：

- [ ] 每个信号的读数，是否只有一种现实解释？不是的话，第二个信号在哪？
- [ ] 确定性层是否只判它真能判准的？歧义有没有如实记录而不是硬判？
- [ ] 证据的时间覆盖是否宽于事件本身？有没有"事前远景"和"事后结果"？
- [ ] 同一时刻是否有候选可挑？挑选依据（清晰度/完整度）是什么？
- [ ] 采集成本是实测的还是猜的？瓶颈定位了吗？
- [ ] 没发生的事是否不占存储？发生了的是否留全？
