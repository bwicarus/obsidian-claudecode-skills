## 一、五组确定性修复(全部按真实字节核对 + 验证)

### G1 — availability 真正独立计算(link_and_mastery.py)
- **病**:progress×availability 只是**字段拆分**不是独立计算。旧派生 `avail = "locked" if st0=="locked" else "open"` 从旧 `state` 反推,而 `state` 里 level≥1 节点恒 `unlockable`(非 locked)→ 这些节点 availability 恒 open。LADR 实测 **4 个 false-open**(availability=open 但直接前置 progress=unseen)。
- **修**:availability **独立**从直接前置的 progress 算(A 语义:所有直接前置 progress∈{in_progress,mastered} 即满足;任一 unseen→locked),不看自身 level、不读旧 state。state 改**诚实派生**:有 progress 时 progress 赢(jump-ahead 节点不因前置缺失被涂灰),否则看 availability。
- **扁平书 guard**:全书 0 prereq 边的背诵书(EGIU,前端 IS_FLAT)不按前置门控,全 open。
- **验**:LADR false-open **4→0**、in_progress 保持 28、EGIU 保持全 open;派生逻辑抽成 `derive_progress_availability_state()` module 级函数(daily/即时重算/测试共用,防漂移)。

### G2 — 服务端一次性 proposal 确认链 + 即时重算(skilltree.py / assistant.py / mastery_overrides.py)
- **病**:①`/api/apply-mastery` 客户端能直接 POST 任意 node+mastery,不需真做过 quiz(无 proposal 绑定);②quiz-grade 不消费 quiz(可重放刷提案);③apply 后无即时重算(要等 daily);④assistant 的 `_t_apply_mastery` **缺 0-1 钳制 + 节点存在校验**(上一轮只修了 skilltree 路由那个);⑤`remove` 掉 override 后 KG 的 `mastery_override` 徽标不消失(`apply_to_kg` 只 set 不 clear,且 `if not ov: return 0` 提前返回)。
- **修**:①新增 `_PROPOSALS` 一次性 token(绑 uid/book/node/value),quiz-grade 铸 id、apply **用服务端权威值**校验归属/未用/未过期后消费;②quiz-grade 消费 quiz;③apply 后 `_trigger_mastery_recompute`(detached,读磁盘 records 不连 Anki);④assistant `_t_apply_mastery` 加 0-1 钳制 + `_kg_all` 节点存在校验 + 诊断背书软标签 + 即时重算;⑤`apply_to_kg` 改**总是遍历所有节点**,无 override 的清残留徽标;新增 `_t_remove_mastery` 工具(用户确认删 + 即时重算清徽标)。
- **验**:proposal 链(首次 OK / 重放 409 / 他人 403 / 错书 400 / 假 id 410)、apply_to_kg set→remove 徽标清理闭环,全绿;webapp 已部署重启健康。

### G3 — 回访 due 语义 + 自测消解(learning_situations.py)
- **病**:①回访用 `上次复习 + ivl` 近似判到期,不是 Anki 权威 `cards.queue/due` → 没到期的卡也可能被拉回;②文档说"自测及格→resolved"但**代码没实现这条腿**;③30 天归档检查跑在"连对两次"**之前**(带 `continue`)→ 刚连对/及格的困难卡被 stale 抢先归档;④回访文案间隔用 `updated` 不是 `resolved_at`。
- **修**:①`detect_revisits` 改读 `col.crt` 算 today + `cards.queue/due`(queue=2/3 复习卡 due≤today、queue=1 学习卡 due≤now、queue≤0 不算);②新增自测消解腿 `_report_resolves_key`(node_results 精确命中 or 整卷 score+报告名命中,≥0.7 及格)+ `check_pass` 证据水位防重复;③归档腿移到两条消解腿**之后**;④文案改 `resolved_at`。
- **验**:queue/due 对真 Anki DB 可读(today=1519,queue=2 有 due=1469 已到期);隔离测试"到期卡拉回 / 没到期卡不动"通过。

### G4 — mention scorer 同基线 + 补 gaps(attention_profile.py)
- **修基线**:`focus_from_mentions` 改用 `events.weight` + 事件内 `1/√N`(N=events.terms distinct 数,与旧打分器**完全一致**);差异**只剩** 多次出现各算 + 父词满记/子词降权。
- **补 gaps**:①`build_mentions` 传 `file` 派生 lang(日语 mention 此前被误标 zh → 现 1619 条正确标 ja);②空 mention 事件写**哨兵行**(idx=-1)避免每次 quick-sync 重抽(2374 哨兵);③拉丁词按**词边界**匹配(tip 不再命中进 multiplication),CJK 保持子串;④`MENTION_VER` 进新鲜度指纹(升版触发重抽)。
- **验**:升 MENTION_VER 1→2 重抽后,新旧打分器 **top15 重叠 12/15**(此前不公平比较是 4/15);剩 3 处差异正是该保留的多次出现/复合词效果。
