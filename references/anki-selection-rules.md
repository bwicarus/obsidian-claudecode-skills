# Anki 制卡判断标准

本文件用于 agent 判断一篇 Obsidian 笔记中的内容是否值得制作 Anki 卡片。**默认倾向：不制卡。** 只有满足严格条件的内容才制卡，宁可少不要多。

制卡判断由 Claude Code / Codex 等外层 agent 完成；`scripts/anki_from_note.py` 只负责读取、同步和写入 records，不调用 AI。

## 核心准则：必要性测试

只有当**主动回忆是必要的**（即，未来使用时如果记不起来，仅靠理解或现场推导无法救场），这个知识点才值得制卡。

制卡前必须能明确回答：**"如果这条记不起来，会发生什么？"** 答案应当是：
- 解题时卡住、表达时找不到词、阅读时无法识别——这种是值得制卡的
- "重新看一眼笔记就行"、"现场推导也来得及"、"不影响理解"——这种**不要制卡**

## 应该制卡（严格清单）

- **核心定义**：未来需要**精确复述**且无法靠语境猜出的术语、对象、符号。
- **判定条件**：解题或证明中**直接用作工具**的必要/充分/等价条件，每条独立成卡。
- **公式定理**：写出后能直接代入使用的公式与适用条件；推导过程不制卡。
- **易混概念**：你**已经混淆过**或在笔记中明确标记需区分的概念对。
- **解题模板**：见到某类问题立刻应该联想到的方法入口（不是"可能有用"，而是"必须想到"）。
- **语言项目**：英/日的单词、短语、语法、惯用表达。
- **个人薄弱点**：笔记中明确标记为不熟/易错/需记忆/需复习的内容。

## 不应制卡（明确排除）

- **理解即可的内容**：第一次看懂后不需要再"想起"的解释、直觉、推导思路。
- **可现场推导的结论**：从已会的定义/定理在 1-2 步内能导出的命题。
- **背景与铺垫**：动机、历史、章节安排、为什么引入这个概念。
- **示例本身**：例子用来说明概念，本体应是概念；除非这个例子需要单独记忆。
- **整页才答得了的问题**：需要大段上下文才完整的内容应拆分，拆不开就不要做。
- **脱离原文含糊的内容**：问题与答案离开笔记就变模糊。
- **学习计划、进度记录、资料索引**。

## 判断流程（必须全部通过）

1. **必要性**：未来使用时记不起来会卡住，仅理解不够吗？
2. **主动回忆**：适合主动产出，而非只适合阅读再认？
3. **原子化**：能拆成一张卡考一个独立知识点吗？
4. **明确答案**：脱离笔记后问题与答案仍然清晰？
5. **不可推导**：不能在 1-2 步内从已掌握的内容现场导出？

**任一不满足，不制卡。** 模棱两可时也不制卡。

## 数量控制（收紧）

- 普通短笔记：**0-3 张**（多数情况是 0-1 张）。
- 信息密度高的概念笔记：**2-6 张**。
- 大段教材摘录：**只挑最核心的 3-8 张**，剩下的留给阅读复习。
- 学习安排、资料索引、摘录目录：返回 0 张。

如果一篇笔记凑不到符合标准的卡，就老老实实返回 0 张，**不要降低标准凑数**。

## 输出判断

- 如果没有值得制卡的内容，返回 `should_create_cards: false`，`cards: []`，并说明原因。
- 如果值得制卡，只生成真正有复习价值的卡片，不要为了凑数量而制卡。
- 无论是否制卡，必须填写 `sections_processed`，列出本次处理的所有节名。脚本据此更新节哈希，避免下次重复处理未变更的节。
