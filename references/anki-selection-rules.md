# Anki 制卡判断标准

本文件用于 agent 判断一篇 Obsidian 笔记中的内容是否值得制作 Anki 卡片。原则是少做低价值卡，多保留需要长期主动回忆的知识。

制卡判断由 Claude Code / Codex 等外层 agent 完成；`scripts/anki_from_note.py` 只负责读取、同步和写入 records，不调用 AI。

## 应该制卡

- 核心定义：后续学习、解题或表达中会反复使用的概念、术语、对象。
- 判定条件：判断某对象是否满足某性质的必要条件、充分条件、等价条件。
- 公式定理：需要主动回忆的公式、定理、结论、适用条件。
- 易混概念：容易混淆、常被误用、需要区分的概念对。
- 解题方法：稳定可复用的步骤、算法、套路、典型题型入口。
- 语言项目：英语或日语中的单词、短语、语法结构、惯用表达、例句。
- 个人薄弱点：笔记中明确标记为不熟、易错、需记忆、需复习的内容。

## 不应制卡

- 纯背景叙述、学习计划、目录、进度记录。
- 只适合阅读理解、不适合主动回忆的长段解释。
- 低价值细节、临时上下文、一次性材料。
- 无法形成明确问答的问题。
- 需要整页推导才能回答的复杂内容。
- 已经在笔记中只是作为例子或铺垫出现、缺少独立复习价值的内容。
- 脱离原文后问题会变得含糊的内容。

## 判断流程

1. 这条知识以后是否会反复用于学习、解题、阅读或表达？
2. 它是否适合主动回忆，而不是只适合重新阅读？
3. 它能否变成一个明确、独立、可回答的问题？
4. 它是否足够原子化，一张卡只考一个知识点？
5. 它是否有明确答案，且答案不需要大段上下文？

通常需要满足第 1-3 条才制卡。若只能勉强转成问题，宁可不制卡。

## 数量控制

- 普通短笔记：0-5 张。
- 信息密度较高的概念笔记：3-10 张。
- 大段教材摘录或课程讲义：优先挑最核心的 5-15 张。
- 如果笔记主要是学习安排、资料索引、摘录目录，可以返回 0 张。

## 输出判断

- 如果没有值得制卡的内容，返回 `should_create_cards: false`，`cards: []`，并说明原因。
- 如果值得制卡，只生成真正有复习价值的卡片，不要为了凑数量而制卡。
- 即使一篇笔记不制卡，也应通过脚本写入 `no_cards` records，避免以后重复消耗 token。
