# 看不见就查不动：一次排查里我三次把"没观察到变化"当成"什么都没发生"

2026-08-18，"电脑语音总是打不开 / 打开又闪退 / 有时要重启 Codex"查了一整天。
最终修好的是六个洞，但**绕的弯路全部来自同一件事**：

> 我没有能观测"语音开没开"的信号，却一直在用观测结果下结论。

> ⚠ 本文与 `silent-failure-lessons.md` 是姊妹篇：那篇讲**程序**出了状况不出声，
> 这篇讲**人**（我）在看不见的时候如何一次次判错。两者常常同时发生 ——
> 程序不出声，于是人只能靠猜，而猜错的代价被下一层的沉默继续盖住。

---

## 一、三次误判，同一个形状

| 我观察到 | 我当时的结论 | 实际 |
|---|---|---|
| 音频会话 Active 持续 45 秒不变 | "Codex 常驻占着麦克风，这个信号跟通话无关" | 语音**当时就是开着的**，信号一直是对的 |
| 按下 F24，五路信号零变化 | "Codex 不响应快捷键" | 是**我从 PowerShell 注入的**按键不生效；桥自己发的有效 |
| 又一次零变化 | "我们没有任何可靠的程序化观测手段" | 三路信号都可靠，是我没做对照实验 |

每一条观察都有**两种解释**：

1. 信号瞎了（探测器不管用）
2. 什么都没发生（这次真的没变）

而我每次都只挑了一种，还都挑错了。更糟的是**第三次是在我已经把结论写进报告之后**，
被用户当场纠正的 —— 他说"我看到你把它打开了"。

## 二、破局的那一下：一次已知为真的状态变化

转折点是用户**手动开关了一次语音**，并告诉我他做了。就这一次动作，
同时给了我两样东西：

- **ground truth**：这一刻确实发生了状态变化
- **对照**：所有候选信号在同一时间轴上的表现

结果一目了然 —— 关闭的瞬间三路信号同时动：

```
[20:13:29] 台账:  stop=0 active=True   ->  stop=…464339 active=False
[20:13:29] 会话:  采集/渲染 Active     ->  会话消失
[20:13:29] 线程:  330 -> 324
```

通话期间采集侧峰值电平在 0.51–0.92 之间跳动 —— 那是真有声音在流。

**一次已知变化，纠正了三个误判。**

## 三、由此定下的规则

### 1. 没有已知为真的状态变化，就不要验证探测器

"我触发一下，看信号动不动" —— 这个实验**天生无效**，因为触发失败和信号失灵
产生的观测完全一样。必须先有一个你**确知发生了**的变化（人手动制造是最可靠的），
才谈得上判断哪个信号跟得上。

### 2. 一次只看一个信号 = 自找的盲区

我前两次都是"只盯着一路信号按一下"。改成**把所有候选信号并排记在同一时间轴上**
之后，答案在第一次实验里就出来了。多记几路的成本几乎为零，而它把
"这个信号不行"和"这次没发生"区分开了。

### 3. 用户的一句话可能就是缺失的那个观测口

「打开语音加载完成时会**叮咚**一声」—— 这句话直接把"就绪"变成了可观测事件
（提示音在渲染侧，峰值电平会出现尖峰）。在此之前我判定"初始化耗时没法测"，
并因此把冷却时间按算术拍成 60 秒；有了这个观测口，实测是 **2.2 秒**，
相关的两个超时常数（20s / 8s）也随之收到 10s / 3s。

**问一句用户"你是怎么看出来它好了的"，可能比我自己想三小时更管用。**

### 4. 常数拍出来之前，先问"这个数我能不能量"

`StartObservationTimeout = 20s` / `StartUsableSettleDelay = 8s` 都是在没有观测手段时
拍的，比实测大了近一个数量级。代价不是"慢一点"，而是**每次失败都要熬满 28 秒才暴露**，
而熬着的时候界面什么都不说 —— 用户感受到的就是"总是出问题"。

拍一个数之前先问：它对应的物理量我能不能测？测不了的话，这个数**必须写明是拍的**
以及依据是什么，好让下一个人知道它可以被改。

### 5. 别让"重试"变成"撤销"

这条是本次最贵的具体教训。F24 是**切换**不是"打开"：按一次开，再按一次关。
而确认信号迟迟不翻转（因为初始化要 2 秒），旧逻辑就判失败、**重试再按一次** ——
正好把刚开起来的关掉。用户原话：

> 刚好看到你打开语音，但是在他初始化完全前就又被关闭了，
> 可我手动打开的语音在初始化结束后留在了那里

手动开的能留下，**恰恰因为没有第二次按键去撤销它**。

对切换型（toggle）操作，"没看到效果就再来一次"是错的。正确做法是：
按下之后等信号翻转，等不到才算失败，而且**等待期间绝不再按**。
冷却时长应当由确认窗口推导，而不是另拍一个数。

## 四、留下的工具

`extensions/bw-reader-webext/windows/VoiceSignalProbe/`（只读，不打包不部署）

四个模式：`--watch`（并排记录所有信号，配合人工制造已知变化）、
`--timing`（100ms 计时，量"按下 → 就绪"）、`--diff`（触发前后快照对比）、
`--hook`（低层键盘钩子，判断注入的按键有没有真的进入系统输入流）。

它的 README 里重复了规则 1 —— 因为**这个工具最容易被拿去做那个无效实验**。
