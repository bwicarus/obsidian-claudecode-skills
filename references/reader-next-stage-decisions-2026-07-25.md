# 阅读器下一阶段产品决定（2026-07-25）

> ⚠ **归档（2026-08-19 核对）**：本文是 2026-07-25 拍板 + 2026-07-26 本地实施状态的**历史记录**，不是现行边界。此后已变更：① 2026-08-14 PWA 阅读页整组退役为 410（`_server_deploy/reader_pwa_retirement.py`），2026-08-18 用户确认只做 iOS App 与浏览器扩展；② 高亮/笔记/词组等数据权威在 App 本地，Pi 只做 AI CLI 的 HTTP 化与设备间同步中继（判据：`python scripts/where_does_this_route_run.py <路由>`）；③ 2026-08-16 起全部工程归 Claude。下文按当时原样保留，只用于追溯取舍，不要据此推断现状。

> 本文记录用户已拍板的方向。实现发生冲突时不得静默删减旧能力，必须保留兼容入口或再次询问。

## 已选默认值

- 复习队列：**1A**，当前内容相关卡优先，不足时混入到期卡。
- 复习对话：**2A**，同一套 AI 侧栏 UI，使用独立的复习逻辑线程。
- 改进旧卡：**3A**，先生成新草稿；旧卡保留，确认后才决定是否替换。
- 卡片合成：**4A**，创建新的唯一组合实体，原卡片保持不变。
- 网页元素选择：**5A**，显式“选择元素”模式；普通点击、触屏滚动和 Safari 原生长按不被全局拦截。
- KG：**6B**，允许自动创建新节点；实现仍须做稳定身份、重复检测、来源证据和可回滚日志，不能按 tag 字符串无条件重复建点。
- 多端同步：**7B**，直接设备连接作为主实时同步方式；服务器仍保留耐久备份与离线补齐，不得因直连成功而漏交服务器备份。

## 旧卡片改进页与复合工具

1. 旧页面继续保留，Anki 卡片中的“问 AI / 改进这张卡”入口也继续可用。
2. 旧页面与复习侧栏不得各自维护生成程序；两者调用同一个卡片改进领域服务。
3. 旧功能中的以下能力必须保留：
   - 选择问答轮次、整段回答或标题下的段落；
   - 更新笔记、改进卡片或两者同时执行；
   - 简洁/详细；
   - 保留原卡或在确认后替换。
4. 旧的卡片改进调用需要迁入现有“单 CLI 多步执行 + 保存执行轨迹/配方”的复合工具体系。
5. 复习工作区的当前卡片下方增加专属操作按钮；按钮和旧页面只改变调用入口，不改变后端程序。

## 上下文包含与缓存

- 选中整张卡片时，内部已选段落不再重复发送。
- 这是发送前对动态上下文做 canonicalize，不删除原始选择记录、不重建系统提示、不改变工具目录。
- 上下文条目使用稳定 id、parentId/covers、确定性排序和确定性序列化。
- 切换整体/子项只改变请求末尾的动态选择快照，避免破坏可复用的静态 Prompt Cache 前缀。

## 工具渐进加载与缓存

- 先建立唯一、不可变、确定排序的 ToolRegistry，再迁移文字、语音、EPUB 和网页工具。
- 阅读/复习模式只改变动态 mode state 与执行端 allow/deny，不在活线程中频繁增删工具 schema。
- 渐进加载只追加，不卸载；需要清空工具域时新建逻辑线程。
- OpenAI Responses 可在支持的模型上使用 namespace + deferred tool search。
- Realtime 整通会话保持工具表不变；复习模式不得通过 session update 反复替换工具表。
- Claude/Gemini/Codex 等不能原生 deferred-search 的路径使用固定核心工具和稳定的 `load_toolset/describe/call` 桥。

## 当前实施顺序

1. 卡片实体编号、来源页、Anki note 与跨设备改进入口的来源链。
2. 唯一卡片改进服务与旧页面兼容接线。
3. ContextSelectionRegistry 与父子包含去重。
4. 复习工作区及卡片下方复合工具按钮。
5. CardCandidateService（直接来源、页面 KG、焦点词、材料图）。
6. ToolRegistry 生产迁移。
7. 自动 KG 建点与直接设备同步。
