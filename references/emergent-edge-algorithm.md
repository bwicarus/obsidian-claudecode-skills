# emergent 边自动连接算法(定稿 v2)—— 算法拼边,AI 只对成品点头

> 用户定调(两轮收敛):① 彻底抛弃预建骨架,节点/边都从学习活动涌现;② **算法和行为做全部预选与组装**
> (候选、方向、证据句都由算法从原文里拼好),**AI 只在最后对一条已拼好的边判"成立/不成立"**;
> ③ 笔记是原子:一篇引用了原文定义句的笔记 = 一个节点 + 若干可抽的边(笔记自动生成,另见上游研究)。
> v1(name-only AI 提名 + AI 读整页六分类)已废——AI 用量太大,且候选/方向不该由 AI 猜。

## 0. 分工总原则

| 环节 | 谁干 | 怎么干 |
|---|---|---|
| 找候选、定方向、抠证据句 | **纯算法** | 别名扫描定义原文(§2)+ 行为共现(§3,辅助) |
| 判"这条边成立吗" | **AI(一句话级)** | 只看算法抠出的证据句,回 prereq / 非前置(§4) |
| 最终签字 | **用户** | confirmed=null 提案 → 技能树上确认/否决(§6) |

AI 的输入从"整页原文+六分类"缩到"一句话+二选一",无法编造关系(证据句是算法从原文抠的,AI 只能解读不能生成)。

## 1. 别名表(纯算法生成,让"导数的定义"能命中原文里的"导数")

每个概念节点 key 的别名集 = 并集:
1. 节点 surface 本身;
2. **event_mentions 里所有 norm_key 归一到该 key 的真实 surface**(用户文本里实际怎么写就认什么,零拍脑袋);
3. 后缀剥离形:剥 `的定义|的基本性质|的性质|求导`(剥后 ≥2 字才保留;「导数的定义」→「导数」,「指数函数求导」→「指数函数」);
4. 手工变体表(极少数,如 Fn → F^n / Fⁿ),存 `state/attention/concept-aliases.json` 可增改。
匹配规则:**最长优先占位**(复用 extract_mentions 的 claimed-span 思路),命中落在更长别名 span 内的丢弃;
拉丁词按词边界,CJK 子串;命中若落在 C 自己的名字/标题行内不算。

## 2. 主机制:别名扫描定义原文 → 自动拼出有向边(零 AI)

对每个概念 C,取它的**定义原文**(来源见 §5),扫描其它概念 A 的别名:
- **A 的别名出现在 C 的定义原文里 ⟹ 候选有向边 A→C**(方向天然:被写进定义的一方是前置侧);
- 证据句 = 命中处所在整句(按 `。．.!?！?\n` 切句),**逐字原文**,随边保存;
- 同一对多次命中取"定义性最强"一句(含「定义/设/称为/是指/依靠/基于/需要」措辞优先,否则取首现);
- A、C 互相出现在对方定义里 → 两条候选都留,交给 §4 的 AI 判和 §7 防环。
实测(2026-07-18,用户笔记):纯算法拼出 `链式法则→指数函数求导`、`导数的定义→指数函数求导`、`导数的定义→泰勒级数`,
各带原文证据句("指数函数求导的思路主要是依靠…链式法则的概念,首先考虑导数的定义写出…")。

**扫不出的就不建**(如链式法则笔记里没写"导数"):笔记里没写出的依赖=弱证据,宁可少连;等笔记变厚自然涌现。

## 3. 辅助信号:行为共现(不定边、不定向)

事件级共现(event_mentions 同 src_key / 同页,过滤 `回收站/.sandbox`,anki_lapse 按卡去重,`COUNT(DISTINCT src_key)` 权重):
- 用途只有三个:**排序**(共现强的候选先送 AI)、**旁证**(边上展示"你也曾在同一页读到过它们")、
  **补漏提示**(高共现但 §2 没扫出 → 提示"这两个可能有关但笔记没写出引用",提醒上游生成/补笔记,而非直接建边)。
- 冷启动实测共现仅 9 对、微积分簇 0 对,**永不当主力**。

## 4. AI 确认(一句话级,每条候选一次,可批量)

输入:候选边 A→C + 算法抠出的证据句(+ 前后各一句上下文,共 ≤3 句)。
问:「证据句里提到了 A。就这句而言,A 是学 C **之前必须先懂**的前置吗?
还是只是:C 的一个例子(instance)/ A 的推广(generalization)/ 顺带提及?」
输出严格 JSON `{"verdict":"prereq|demote|drop","reason":"≤15字"}`:
- `prereq` → 落有向边;
- `demote` → 落**无向 related**(instance/generalization/提及,不进解锁门控);
- `drop` → 不落边。
调用:`make_backend("claude_cli",{model:"sonnet",effort:"low"})`,10 条一批打包一次调用;
结果按 `(a,c,句子sha8,ver)` 永久缓存 `state/attention/edge-confirm-cache.json`,句子没变零成本。

## 5. 定义原文从哪来(与"笔记为原子"对接)

优先级:
1. **该概念的自动/手写笔记正文**(000-xxx.md,去 frontmatter/ankicards)——笔记就是用户学它的原文载体;
2. in_authored_kg 节点 → `authored_ref` 反查 KG `pages` → `AP._page_text(rel, page, limit=8000)`(**必传 8000**,默认 400 截断定义句);
3. 都没有 → 该概念暂只当孤立节点,不参与拼边(诚实降级)。
上游"笔记自动生成"(注意力触发 + 引原文定义句)= 让 1 越来越全的机制,规格另文(研究中):
生成笔记时**必须逐字引用原文定义句**——这是边能被 §2 扫出的前提;AI 解释层单独分区、不参与扫描。

## 6. 提议→确认闸(先修,零 AI)

v1 遗留 bug:边的确认写入→读取→下游全断(用户点边确认/否决零效果)。修法不变:
1. `build_unified_graph.py` emergent 边循环读 `conf["edges"]["from|to|kind"]`:False→丢弃、True→confirmed、None→provisional;
2. `skilltree.py::skilltree_unified_confirm` 加 edges 写分支;
3. `promote_concepts.build_edges` 落盘前按 (from,to,kind) 前向合并旧 confirmed(不再 rebuild 即清签字);confirmed 边掉出候选打墓碑;
4. 下游(为什么锁/诊断链)把 `confirmed is not True` 的 emergent 边当暂定,不进硬门控。

## 7. 方向与环

- 方向 100% 由 §2 的"谁被写进谁的定义"决定,AI 只能降级(demote/drop)不能改向;
- prereq 边收齐后拓扑排序,检出环只剔**证据最弱**(共现权重最低/证据句非定义性措辞)的一条,重跑至无环;
  只在 confirmed==True 边间做破坏性操作,提案层的环整体标出留给用户裁。
- 传递归约:仅 A→B、B→C 都 confirmed 后把直连 A→C 标 `shadowed`(不删,可恢复)。

## 8. 分期

| Phase | 内容 | AI 用量 |
|---|---|---|
| **0** | §6 修确认闸(纯管线) | 0 |
| **1** | §1 别名表 + §2 别名扫描拼边 + §4 一句话确认,替换现 `--edges` 内核 | ~10 句/一批,几分钱 |
| **2** | §3 共现辅助接入(排序/旁证/补漏提示) | 0 |
| **上游** | 笔记自动生成(注意力触发+引原文定义),另文定稿后接入 §5 | 生成时一次 |

## 9. 数据结构(沿用 v1,微调)

边:`{from,to,kind:prereq|related,origin:"emergent",confirmed:null|true|false,method:"aliasscan+sentconfirm",`
`quote:"<证据句原文>",quote_src:"note:000-x.md|LADR#id@p13",strength:<共现权重>,rel_detail:"<AI verdict>",ver:2}`
确认存储/缓存文件同 v1(§1.2/§1.3),缓存键的 text_sha8 改为**证据句** sha8。

## 附录:v1→v2 变更理由(实测)
- name-only AI 提名废除:候选/方向不该 AI 猜;别名扫描在真实笔记上直接拼出微积分 3 条边+证据句,零 AI。
- AI 读整页六分类降为一句话二选一:输入从 ~8K 字/对降到 ~100 字/对,且证据句算法抠取后 AI 无法造边,v1 的三道防造边闸自然不需要。
- 共现主力降为辅助(冷启动 9 对、微积分 0 对,当主力会清零正确链)。
