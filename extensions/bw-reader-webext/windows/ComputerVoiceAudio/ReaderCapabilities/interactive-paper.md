# 交互练习纸

用户说“让我写”“在纸上做”“出题后批改”“考考我”“出张卷子/听写”时，目标是 Reader 内
可手写作答的交互纸，不是 Anki 卡片，也不是普通信息卡。

## 原生编排合同（一发式）

1. 根据用户原话与必要的当前页内容，自己设计题目、作答区和排版顺序。
2. 把整张纸一次性交给 `reader_paper_start`：`blocks` 按阅读顺序给全部元素，参数
   schema 以该工具的 inputSchema 为准。要点：
   - 题干/说明用 `text`（内容放 `text` 字段，标题可 `style:"h1"`）；
   - 手写作答区用 `blank`（题号或整题放 `label`；`answer` 字段留标准答案供事后批改）；
   - 选择题必须用 `choice`（题干 `text` + `options` 数组，别把选项塞进 blank）；
   - **不要放批改按钮**：批改是对话式的——用户说“检查/批改”时，用 `reader_visual_image`
     截取纸面（含手写墨迹），对照你出题时的 `answer` 逐题批改并口头反馈；
   - `button` 仅在用户想要纸内交互（`reveal:块id` / `hide:块id` 显示答案等）时按需放。
3. 布局、建页、渲染、多页补页全部发生在 Reader 内；纸约两秒内出现在打开的书里。
   仅支持 PDF 书页；快照表面不是 PDF 时工具会明确拒绝，不要换别的表面重试。
4. 结果不会回传：一次调用后**不得盲目重发同一张纸**。落盘是否成功，用用户的确认或
   新快照来判断；不确定时先问，不重建、不重复添加。

## 标准答案与来源

- 默认用用户指定范围；没有指定时，以当前快照所指的书页或章节为范围，不擅自扩成整本书。
- 用户要求“核实答案”时，先以书内可取得的原文为证据；只有用户要求外部核实，或书内材料
  无法裁决时，才增加开放网络或其他权威来源。书内证据与外部证据分开标注。
- 需要两条独立证据流时可让原生子代理只读核实；题面设计、纸张写入与最终裁决仍由主 agent
  负责。无需再读 `check-report`：该 topic 用于已经生成的检查报告，不用于造纸前答案核实。

若当前会话没有 `reader_paper_start` 工具，明确返回“交互纸服务能力未暴露”。不要退化成
卡片、图片或启动一个旧 CLI worker 来冒充完成。旧 CLI 造纸实现保留为兼容路径，但不属于
Windows Codex 原生路由。
