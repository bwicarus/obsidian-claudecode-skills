# 交互练习纸

用户说“让我写”“在纸上做”“出题后批改”时，目标是 Reader 内可手写作答的交互纸，
不是 Anki 卡片，也不是普通信息卡。

## 原生编排合同

1. 根据用户原话与必要的当前页内容设计题目、作答区和布局。
2. 当当前会话暴露服务端纸张工具时，先按服务能力发现取得实时 schema，再依次执行
   `page_new`、一个或少量批量 `page_add`、`page_show`；不要按旧记忆猜参数。
3. 题干使用文本元素，作答区域使用 blank。需要批改的纸必须放一个“让 AI 检查”按钮，
   其事件为 `check`；答案或提示的显示/隐藏按实际任务设计。
4. 写操作由主 agent 执行。任何一步的结果若不确定是否落盘，不得重建或重复添加。

## 标准答案与来源

- 默认用用户指定范围；没有指定时，以当前快照所指的书页或章节为范围，不擅自扩成整本书。
- 用户要求“核实答案”时，先以书内可取得的原文为证据；只有用户要求外部核实，或书内材料
  无法裁决时，才增加开放网络或其他权威来源。书内证据与外部证据分开标注。
- 需要两条独立证据流时可让原生子代理只读核实；题面设计、纸张写入与最终裁决仍由主 agent
  负责。无需再读 `check-report`：该 topic 用于已经生成的检查报告，不用于造纸前答案核实。

若当前会话没有纸张创建工具，明确返回“交互纸服务能力未暴露”。不要退化成卡片、图片或
启动一个旧 CLI worker 来冒充完成。现有旧 CLI 造纸实现保留为兼容路径，但不属于 Windows
Codex 原生路由。
