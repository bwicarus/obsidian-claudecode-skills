# 语音入口

收到开头是「语音入口」的主动通知时，按下面的顺序做。**中途成功就停下。**

## 第一步：跑一次入口脚本

    python "%LOCALAPPDATA%\BWReader\voice_start_step.py"

它会打印一行 JSON，并且**自己会等**（最多约一分钟），不用你另外计时。
看 `confirmed`：

- `true` —— 已经进入语音，**到此为止**，不要再跑。
- `false` —— 还没进，去第二步。

顺带看一眼 `reason`，第三步要用：
`already-active`（本来就在通话，等同成功）、`started`、`cooldown`（刚按过，
稍等再看，不算失败）、`not-confirmed`、`unknown`（读不到状态）、
`voice-off`（这台机器没装语音层）、`unreachable`（连不上）。

## 第二步：再跑一次，只再跑这一次

同一条命令，原样再跑一次。`confirmed` 为 `true` 就到此为止。

## 第三步：还是不行就放弃，并把这件事说出来

    python "%LOCALAPPDATA%\BWReader\voice_start_failed.py" ^
      --attempts 2 --detail "<第二次的 reason>"

⚠ **不要跑第三次入口脚本。** 两次不成就是不成，继续按只会拖长等待。
⚠ **不要自己另想办法去开语音。** 没有别的正确办法，试出来的都是错的。
⚠ **放弃必须跑这一步。** 不报错的放弃跟"还在试"在界面上长得一模一样：
按钮一直闪，人一直等，而其实早就不会成了。

## 为什么不用你自己判断该不该按

入口脚本自己会看状态：已经在通话就不按（那个按键是切换，再按一下是关掉），
状态确实读不到也不按。需要的前置条件它也会自己准备好 —— 该开的东西没开着，
它会先开起来再等就绪，你不用先做任何准备动作。

所以直接跑就行；连着跑两次也不会做出相反的事。

## 有人问你状态的时候

那是另一件事，见 `status-report.md`。状态查询**只要回答**，不要顺手去开语音。
