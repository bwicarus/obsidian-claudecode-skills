# 展示板（iOS 小组件上那块分了区的板子）

给「一段时间里要**反复看状态**」的任务用：每日某个方面的新闻、某个产品的发布、
某个长跑任务的实际进展。变化发生时的通知已经另有一套；这块板子解决的是
「我现在想扫一眼它到哪了」。

它就是一块板子：**几个分区，每区几行字**。它不会替你排版，也不解释内容。

## 什么时候用（这一条最重要）

**只有用户在任务里明确说了要用展示板，才用。** 不要自己判断该不该开一块板子，
不要"顺手也放一份到板子上"。用户的原话：

> 这个展示板的使用是用户在创建任务时明确说明需要开启的，所以不需要 ai 自行判断
> 是否开启。

同理，**`enable` 这个 op 是用户的开关，你永远不要调它**。用户在 App 里开关，
关掉的板子就不会出现在小组件上 —— 那是他的决定，不是你的。

## 接口

一个端点，POST JSON，body 里的 `op` 决定做什么：

```
POST https://bwicarus-2.taile44d0c.ts.net/reader-board/v1
```

本机上的固定程序也走这个地址（自己的 tailnet 名字），跟设备同一条路、同一套鉴权。

回执一律 `{"ok":true, …}`；失败是 `{"ok":false,"error":"BW_BOARD_…","detail":"…"}`，
`detail` 会说清是哪个字段、超了多少 —— **按它改，不要原样重试**。

### 第一步：注册，拿编码

```json
{"op":"register", "slug":"daily-ai-news", "title":"每日 AI 新闻",
 "note":"用户 9/5 的任务要求", "autoClear":{"kind":"dailyAtLocal","hhmm":"04:00"}}
→ {"ok":true, "code":"bd_1f9c3a7b28d4e05f", "created":true, "enabled":true}
```

- `slug` 是**你自己起的稳定名字**（同一个任务每次用同一个）。
- **register 对同一个 slug 是幂等的**：再注册一次拿回同一个 `code`。所以固定程序
  每次运行都可以先 register 再更新，**不需要自己保存 code**（自己存就会丢，
  丢了就再也更新不了那块板子）。
- `note` 写一句"这块板子为什么存在"。用户在 App 里看到的就是这句。
- `autoClear` 可选，见下。

### 放内容：整块替换

```json
{"op":"update", "code":"bd_…",
 "sections":[
   {"title":"今日要点", "lines":["OpenAI 发布 …", "Anthropic …"]},
   {"title":"值得读", "lines":["…"]}
 ]}
→ {"ok":true, "code":"bd_…", "sections":2}
```

### 放内容：只改一个分区（增量）

```json
{"op":"section", "code":"bd_…", "title":"运行状态",
 "lines":["第 3/8 步：抓取完成", "耗时 12 分钟"]}
→ {"ok":true, "section":"运行状态", "replaced":true}
```

同名分区**整区替换**；没有就新增。反复更新同一个分区是常态用法 ——
每轮把那一区重写一遍即可，不要每次新建一个分区。

### 清空 / 删除 / 查询

```json
{"op":"clear",  "code":"bd_…"}                 // 清掉所有分区（板子还在）
{"op":"clear",  "code":"bd_…", "section":"今日要点"}   // 只清一区
{"op":"delete", "code":"bd_…"}                 // 整块删掉
{"op":"get",    "code":"bd_…"}                 // 取回这块板子的全部内容
{"op":"list"}                                   // 列出所有板子（不含正文）
```

任务结束、板子不再有意义时 **`delete`** 掉。留一块永不更新的板子在用户桌面上，
比没有更糟。

### 自动消除（可选）

```json
"autoClear":{"kind":"never"}                       // 默认
"autoClear":{"kind":"afterHours","hours":6}         // 某区 6 小时没更新就撤掉那一区
"autoClear":{"kind":"dailyAtLocal","hhmm":"04:00"}  // 每天本地 04:00 整块清空
```

- `afterHours` 撤的是**分区**，不是板子 —— 适合"运行状态"这类过期就无意义的内容。
- `dailyAtLocal` 适合"每日新闻"：早上清空，当天重新填。
- 结算发生在**每次读写**时，不靠定时器（小组件不在这个进程里，定时器帮不了它）。

## 格式要求（照着写，别自由发挥）

- **分区最多 12 个**，每区**最多 24 行**，每行**最多 200 字**，标题最多 60 字。
  超了直接被拒（`detail` 会说超了多少），不会悄悄截断。
- 每行是**一句能独立看懂的话**。小组件那块地方很小，一行只显示一行，
  写成长段落等于只看得见开头。
- **不要放 Markdown 标记**（`**`、`#`、`-`）—— 板子不渲染它们，会原样显示成噪声。
  要强调就把重点写在句首。
- **不要放时间戳**。板子自带"数据时刻"，你再写一遍只会占掉一行，
  而且两个时间不一致时用户会以为板子坏了。
- 每次更新都把那一区**写完整**（整区替换语义）。只写增量会丢掉上下文。
- 空行、纯空白行会被丢掉，不必自己排版留白。

## 一个完整的例子（固定程序每小时跑一次）

```json
{"op":"register","slug":"deploy-watch","title":"发布看板",
 "note":"用户要求盯 X 产品发布","autoClear":{"kind":"afterHours","hours":12}}
{"op":"section","code":"bd_…","title":"当前状态",
 "lines":["尚未发布","官网版本号仍是 4.2","下一次检查 1 小时后"]}
{"op":"section","code":"bd_…","title":"已确认的信号",
 "lines":["开发者论坛出现 4.3 beta 讨论","官方 changelog 未更新"]}
```

发布真的发生时：更新板子，**并按原有通知能力通知用户** —— 板子是"随时可看"，
不是"通知的替代品"。用户的原话是「这个作为一个 ai 可选的通知功能就好」：
板子补的是他主动想看的那一刻。
