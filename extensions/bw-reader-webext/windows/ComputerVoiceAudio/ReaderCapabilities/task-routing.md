# Codex 原生任务路由

目标是让普通语音请求没有固定附加延迟，只为真正复杂的任务付出研究成本。

## 快速路径

- 不需要 Reader 实时事实：直接回答，不调用 Reader 工具。
- 当前页、选区或阅读窗口：一次 `reader_context_snapshot`。
- 当前合成图：一次 `reader_visual_image`；不要先把整页正文塞入任务。
- 滚动或定位：一次 `reader_browser_control`，随后只有需要新正文时才重读快照。
- 卡片、导航、高亮、工具状态：一次 `reader_command`。

这些单步请求不先读能力文件，也不启动子代理。

## 复杂路径

保留用户原话。需要当前书时只读一次快照，再按任务读一个对应能力文件。顺序依赖的工具调用
由主 agent 完成；只有两条以上互不依赖的证据流、跨多个来源的核实或长篇综合才使用 Codex
原生子代理。子代理默认只读，主 agent 负责结论与所有写操作。

不要从 Windows 原生路径启动 `codex exec`、Claude CLI 或旧后台 worker。现有 Realtime 与
旧 CLI 代码保持不变，属于兼容路径而不是本路由的下一层。

## 写入与重试

执行写操作前确认用户已要求该动作，必要时重新读取当前快照。失败回执若不能证明“未执行”，
状态就是未知；不得盲目重试纸张、卡片、高亮、便签或已保存任务。长任务可用
`tool-status` 报开始和结束，但不要为短任务多发状态轮次。
