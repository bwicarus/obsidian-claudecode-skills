# Surface Pen 真机验收清单

这份清单只验证 Windows Chrome 的硬件 direct-manipulation 路径。CDP 合成 `pointerType=pen`
只能覆盖 JavaScript 状态机，不能代替真笔测试。

## 测试前

1. 确认测试通道版本严格高于当前已部署版本，并通过 `release_preflight.py`。
2. 用桌面上的 **BW Extension Test** 更新固定 unpacked 目录。
3. 在 `chrome://extensions` 确认 **BW网页伴读** 已启用并点击一次“重新加载”，再刷新网页。
4. 使用普通长页面测试；同时准备一个含按钮、链接、输入框的页面和一个书籍 PWA 页面。

## 主动笔与原生网页

- 笔尖悬停后直接落笔：第一笔立即出现，页面不能先滚一下再开始画。
- 连续快速画短线和长线：笔迹紧跟笔尖，不跳点、不出现“慢半拍”。
- 笔侧键不应误画；Surface Pen 笔尾落笔应临时擦除，翻回笔尖后立即恢复画笔。
- 笔尖悬停后落在网页正文链接、按钮或输入框上仍按绘图处理，这是“笔与图层唯一绑定”的
  已确认取舍；不要把它误判为回归，也不要在真机验收时临时改成笔尖点击。
- 鼠标和手指仍能点击链接/按钮、选择文字、聚焦输入框；鼠标滚轮保持网页原生行为。

## 手指、滚动与系统防误触边界

- 显示 canvas 必须始终穿透；唯一参与命中测试的是跟随笔尖的自动预命中区，宽高都不得
  超过 32px。它只为真笔在接触前声明 `touch-action:none`，不得扩大为全页输入层。
- 笔或橡皮抬起后，手指恰好从最后笔尖坐标开始上下滑：**第一轮**手势就必须原生滚动，
  不能要求再点一次或等待定时器；笔尖在原点 8px 内轻微抖动也不能让热点重新出现。
- 笔尖从上次抬笔位置明确移动超过 8px 后，32px 预命中区应立即重新武装，下一笔落下时
  页面不能跟着滚。连续书写时重点验证这里既不漏笔，也没有明显等待。
- 若手指恰好在“笔尚未落下但 32px 热点已武装”的极小区域内开始，当前手势可能因浏览器
  已完成仲裁而失效；手指落下必须同步撤销热点，下一轮手势必须恢复。这是用户选择的自动
  混合边界，不得用 140px 旧盾、整页 `touch-action:none` 或自制惯性滚动掩盖。
- 快速交替“笔写—手指滚—笔写”：不得触发重复落笔、卡死或永久阻断触摸。
- 笔按下未抬时手指落下，热点也必须立即撤销；抬笔后网页不能留下触摸锁。
- 连续两次快速短滑必须仍是滚动，不能被“触屏双击切橡皮”误判。
- 普通上下滚动不改变排版宽度时，已完成笔迹应与文档同步滚动，不应迟半帧追赶。
- 分别测试“笔仍悬停在玻璃上方”和“笔已经移出屏幕感应范围”。若前者完全没有 touch
  `pointerdown`、或系统立刻发 `pointercancel`，这是 Windows/设备掌触抑制而非扩展残留锁；
  记录现象与系统“使用笔时忽略触摸输入”设置，不得再用网页定时器或扩大热点掩盖。

## 临时绘图与排版变化

- 刷新或关闭标签页后，普通网页笔迹应消失；历史 `webInkV1` 数据不应被覆盖或删除。
- 拖动侧栏使网页内容宽度改变后，临时笔迹应被清空并出现提示。这是预期行为，因为重排后
  原内容坐标已经失效。
- 仅打开悬浮侧栏、普通滚动或浏览器高度变化时，不应误清空笔迹。
- 在书籍 PWA 中启用扩展时只出现一套共享 UI；停用/重载扩展后 PWA 原生 UI 能恢复。

## 失败时记录

请同时记录：扩展版本、Chrome 版本、Surface 型号、笔型号、测试网址、是否连接外接屏、
Windows 缩放比例，以及问题发生前的最短操作序列。若是滚动/落笔问题，再录一段包含笔尖和
屏幕的慢动作视频；仅录屏看不到硬件接触时序。
