# Skill: 协作邮箱（与 Codex 交接）

Claude 与 Codex 之间的持久双向任务邮箱。**不需要人工转述，也不接管对方的桌面会话。**

## 触发方式

用户提到「告诉 Codex」「问一下 Codex」「跟他商量」「查邮箱」「有没有新消息」，
或你自己**开始一段工作前 / 完成一段工作后 / 需要对方配合时**，都用它。

## 什么时候必须查

| 时机 | 为什么 |
|---|---|
| **开工前** | 对方可能已经认领了你要动的文件，或留了边界约束 |
| **完工后** | 交接不写下来，下一个人（包括未来的你）要重新推一遍 |
| **需要协助 / 要动到对方范围时** | 跨机双写同一文件是冲突源 |

## 命令（在 `C:\claude` 下跑，Windows 记得 `PYTHONUTF8=1`）

```powershell
python scripts\agent_collaboration.py inbox --agent claude
python scripts\agent_collaboration.py ack --agent claude <消息ID>
python scripts\agent_collaboration.py reply --from claude <消息ID> --body "<正文>"
python scripts\agent_collaboration.py send --from claude --to codex --subject "<主题>" --body "<正文>" --scope "<文件或范围>"
python scripts\agent_collaboration.py wait --agent claude --reply-to <消息ID> --timeout 60
```

- `wait` 超时返回**退出码 2，这不是错误**。
- 加 `--json` 得到机器可读输出。
- 长正文用 PowerShell here-string（`@'` … `'@`，结束符必须顶格）。

## 消息怎么写

**发出的每条**要说清：想要的结果、涉及的文件或范围、**是否只读**。

**回复的每条**用四段式（Codex 侧同一约定）：

```
改了什么 / 验证了什么 / 没做什么 / 下一步谁做
```

「没做什么」不是客套——它是防止对方假设你已经做了的唯一手段。

## 边界

- 邮箱数据在 git 之外（`%LOCALAPPDATA%\BWAgentCollaboration\mailbox.sqlite3`），不入库、不开端口。
- **不要与对方同时编辑同一文件。**要并行就各开分支 + worktree。
- v1 **不会**把消息自动注入对方正在进行的桌面会话——对方要自己查。所以急事仍需用户转达。
- 未来两台机器分离时，不共享 SQLite，而是经既有 SSH 在 Windows 上跑同一条命令取 stdout。
